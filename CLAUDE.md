# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository contents

This repository holds a single self-contained HTML slide deck:

- `FinnOne Neo LMS - Board Strategic Assessment (1).html` — a board-level strategic assessment presentation for Nucleus Software's FinnOne Neo loan servicing platform (LMS), covering market trends, a capability/gap analysis, a SWOT, and a phased roadmap.

There is no build system, package manager, or test suite. The file is opened directly in a browser — no compilation or dev server is needed.

## Working with the deck

Everything — markup, CSS, data, and JS — lives in this one HTML file. To preview changes, just open the file in a browser (or reload it after edits).

### Structure of the file

1. **`<style>` (head)** — all styling, driven by CSS custom properties under `:root` (the `--navy-*`, `--ice`, `--gold`, `--text-*` palette). Change the deck's look by editing these variables rather than hardcoding colors in rules.
2. **`<body>`** — a horizontal deck of `<section class="slide" id="..." data-section="...">` elements inside `#track`. Each slide's `data-section` attribute drives the top bar's section label. Slide order in the DOM is the presentation order; navigation moves `#track` via `translateX`.
3. **`<script>` (end of body)**:
   - `base64Logos` — a large map of company-name → base64-encoded logo image, used by `logoChip()` to render partner/competitor logos inline (no external image requests).
   - Content data arrays/objects (e.g. `eras`, `regions`, `compareRows`, `capRows`, `swot`, `strengthDetails`/`weaknessDetails`/`opportunityDetails`/`threatDetails`, `phasesData`, `marketValues`/`marketYears`) — these hold the actual slide content (SWOT items, roadmap phases, market-size chart data, etc.). **To update the deck's content, edit these data structures**, not the HTML — the corresponding slide sections are rendered from them at load time.
   - `render*()` functions (`renderEras`, `renderRegions`, `renderCompareTable`, `renderCapGrid`, `renderSwotMatrix`, `renderDetailGrid`, `renderPhases`, `renderMarketChart`) — each populates one interactive slide section from its data array via template-literal HTML injection, then wires up any tabs/click-to-expand behavior for that section.
   - Deck navigation engine (`goTo`, keyboard arrows/Home/End, touch swipe, dot/segment nav, prev/next buttons, fullscreen toggle) — generic slide-advance logic that operates on whatever `.slide` elements exist; it does not need to change when slide content changes.

### Common edits

- **Change slide content/copy**: edit the relevant data array in the `<script>` block (see above) rather than the rendered HTML, since most data-driven slides are regenerated by their `render*()` function on load.
- **Change static slide markup** (e.g. cover slide, section-intro slides that aren't data-driven): edit the `<section class="slide">` HTML directly.
- **Add a new slide**: add a new `<section class="slide" id="..." data-section="...">` in `#track` in the desired position; the nav engine picks it up automatically via `document.querySelectorAll('.slide')` — no other wiring needed.
- **Add/replace a logo**: add a base64 data URI entry to `base64Logos`, keyed by domain, so the deck stays fully self-contained with no external network requests.
